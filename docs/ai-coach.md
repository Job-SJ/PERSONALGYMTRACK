# AI Coach

Coach is optional. The deterministic dashboard, training analytics and adaptive nutrition work independently.

1. Ask the instance administrator to apply the Coach migrations, including `202611280001_coach_chat.sql`, and set up the credential vault. [Credential vault setup](self-hosting.md#hevy-credential-storage)
2. Create an [OpenRouter inference key](https://openrouter.ai/settings/keys). Set a provider-side credit cap. Disable prompt and response logging, prompt sharing and any observability exports that record content in the OpenRouter workspace. An administrator may provide a separate capped instance key using `OPENROUTER_INSTANCE_KEY`.
3. Open **Coach → Settings** in the web or Expo app. Choose the key source, enter a personal key if needed, then test the connection. GymTrack encrypts a new key before storing it.
4. Choose a model and hosting endpoint. Review free or paid pricing, required Zero Data Retention, supported parameters and the monthly USD budget. A zero budget works for eligible free endpoints. Grant consent and enable Coach.
5. Type a fitness question or start from a suggestion. Ask follow-up questions in the same chat. Replies stream when the connection supports it. Use **Stop** during generation or **Retry reply** after an interrupted answer. Conversations sync across your signed-in devices. Use **New chat** to change topics, and select a saved chat to rename or delete it.

Existing Coach users must grant fresh consent for conversational chat. **The selected AI provider processes your typed messages, recent conversation history, and summarized fitness records.** Leave credentials and identifying details out of messages.

The app queries OpenRouter's current Zero Data Retention endpoint catalog, pins the approved model and endpoint, requires `zdr` and `data_collection: deny`, disables fallback and caps pricing per token. An unavailable or changed model requires reviewing settings. OpenRouter workspace settings and its own metadata and retention policies remain relevant. The inference API does not expose a way for GymTrack to audit your workspace's logging configuration. [OpenRouter routing](https://openrouter.ai/docs/guides/routing/provider-selection) · [Zero Data Retention](https://openrouter.ai/docs/guides/privacy/zdr)

GymTrack builds a structured summary using the existing deterministic analytics. It includes recent training and historical comparisons over up to 60 days, estimated strength, nutrition trends and targets, bodyweight averages, and active goals. The summary uses a small catalog of canonical exercise names and excludes workout notes, custom labels, account IDs and credentials. Each request includes the current question and up to four recent completed turns, subject to an 8,000 UTF-8 byte context limit. The model receives no tools or database access. Coach treats generated Markdown as text and formatting without loading remote images or rendering raw HTML.

Coach requires explicit input and output token prices and treats an omitted per-request fee as zero. It skips endpoints with safety retention, insufficient token capacity, missing output-limit support, or charges it cannot cover with the token reservation. Free endpoints must pass the same checks as paid endpoints. If setup finds no eligible models, it shows whether the ZDR catalog was empty or how many endpoints failed each check.

Budget reservations and a cooldown are enforced in the database per user. An interrupted or invalid upstream response may keep its estimated reservation until the next UTC month. The provider-side key limit is the external billing backstop. Administrators who share an instance key should set an aggregate provider cap before enabling it.

GymTrack stores up to 100 conversations per account and 120 questions per conversation. Conversations remain available until you delete them. Use **Coach settings** to change provider configuration, withdraw consent, remove the personal key or delete all conversations. Deletion removes messages and replies and preserves non-content billing counters. OpenRouter's handling of prior requests and Supabase backup retention follow their respective settings and policies.
