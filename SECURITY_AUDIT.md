# PERSONALGYMTRACK security assessment

Scope covers the feature branch, its application source, the production build on loopback, and the migration and integration tests using synthetic records. No live workout, nutrition, or bodyweight records were read or modified. No live Hevy, Supabase, or production infrastructure was probed.

Verification references include OWASP Top 10:2025 A01 access control, A02 configuration, A03 dependencies, A05 injection, A07 authentication, and A09 logging. ASVS 5.0.0 guidance covers validation, web frontends, authentication, sessions, authorization, configuration, and logging. [OWASP Top 10](https://top10.owasp.org/) · [OWASP ASVS](https://asvs.owasp.org/)

## Findings

| ID | Category and severity | Affected component | Evidence and verification conditions | Potential impact | Remediation and retest |
| --- | --- | --- | --- | --- | --- |
| PGT-01 | Session configuration · Medium | Supabase SSR cookie writes in `lib/supabase.ts` and `proxy.ts` | Reviewing both production cookie writers and the installed SSR package defaults showed HTTP-only was enabled but Secure was unset. Applies when a production session is issued or refreshed and the host is reachable over HTTP. | The browser can send a session cookie over plaintext before an HTTPS upgrade if HSTS is absent from its state. | Remediated by setting Secure in production through the shared cookie policy used by both writers. Unit tests verify both policies. A production Chromium sign-in through a loopback Auth fixture confirmed Secure, HttpOnly, and SameSite=Lax on the emitted cookie. A hosted HTTPS retest remains open. |
| PGT-02 | Server-side request destination control · Low | Open Food Facts integration in `app/nutrition-actions.ts` | The food URL builder selects a fixed HTTPS provider. The fetch previously used the default redirect behavior, so the fixed origin constrained only the first request. Cross-origin reachability from untrusted app input was not established. | A provider-controlled redirect could cause the application server to contact an unintended destination. | Remediated by rejecting redirects, consistent with the existing Hevy client. The mocked transport retest verifies redirect rejection is configured and failures return a generic response. |
| PGT-03 | Authentication and abuse controls · Informational | Supabase Auth and protected form actions | Sign-in and reset responses are generic. Provider signup settings, quotas, token lifetimes, recovery redirects, and enforcement under repeated requests require deployment access. Food search, CSV import, and Hevy's connection test have input or time limits, but the source does not define per-account request budgets for these actions. | Effective protections against abuse and authentication attempts depend on provider and deployment controls. | Open deployment verification item. Record actual provider quotas, verify invitation and recovery using synthetic accounts, and evaluate request budgets for costly actions in a dedicated environment. |
| PGT-04 | Sensitive account changes · Informational | Password changes and MFA setup | The actions require the authenticated application session, and enrolled TOTP accounts must present AAL2. The password change handler delegates to the provider without requesting fresh credentials. Provider secure password change settings were outside the available environment. | Assurance for sensitive changes depends on the age of the session and provider settings. | Open deployment verification item. Review provider reauthentication policy and verify behavior with fresh and older sessions. |
| PGT-05 | Verification coverage · Informational | Private production deployment and direct Supabase API | The automated isolation suite runs the actual SQL against PGlite and switches between two synthetic owners and role claims. It does not mint provider sessions or reach PostgREST. ZAP was unavailable locally. | Provider configuration, deployed roles, browser session lifecycle, and edge behavior may differ from local verification. | Open. Run direct API isolation, cookie and session lifecycle checks, and a passive baseline scan against an approved disposable deployment before release. |

## Verified behavior and scope limits

| Area | Evidence | Remaining verification |
| --- | --- | --- |
| Private routes and export | Playwright setup coverage checks that private training requires configuration and that unauthenticated export returns a redirect with no attachment and restrictive cache and frame controls. A configured production build using a loopback Auth fixture also verified anonymous redirects, successful sign-in, a recovery request, and local cookie removal on sign-out. Protected pages, export, synchronization, and nutrition actions call `session()`. | Provider-backed login, invitation, reset, MFA enrollment, logout token invalidation and expiration using two disposable accounts. |
| Ownership and database grants | PGlite applies the checked-in migrations and tests synthetic cross-account workout and nutrition reads and writes, bodyweight reads and writes, authenticated role restrictions, AAL1 denial when a factor is verified, and sync owner constraints. The database uses ownership policy, explicit grants, and an invoker workout RPC. | Direct PostgREST checks with real provider-issued test JWTs, deployed grants, and hosted query plans. |
| Validation and output encoding | Source review covered schema-based form and JSON validation, fixed redirect routes, React text rendering, request-size limits, CSV file-size checks, and JSON attachment export. The application has no CSV export or webhook receiver. Existing tests cover nutrition data normalization and parsing behavior. | Dedicated runtime checks for all malformed input classes, resource limits, environment-specific CSRF behavior, and enumeration or rate limiting. |
| Integration boundaries | Hevy uses server-side GET, a fixed origin, redirect rejection, timeouts, schema validation, an owner check, and a database sync lease. Mocked sync tests cover reconciliation and retries. Nutrition lookup uses bounded input and timeout. | End-to-end Hevy synchronization against an approved synthetic account and external API configuration checks. |
| Supply chain and secret exposure | npm audit reported zero known advisories in the installed lockfile. A restricted history and filename scan for representative credential formats found only the tracked environment template by filename. | Full secret scanning and credential inventory, deployed client bundle and source-map review, and private repository access review. The local production static directory had zero source maps or matches for the checked secret formats. |
| Browser and infrastructure | Nonce-based CSP prohibits external scripts, embedding, and objects. Header tests cover cache and frame behavior. Production routes are dynamic. Camera permission is scoped to the nutrition route for the browser barcode scanner. | Deployed HTTPS, HSTS, proxy/CORS behavior, and passive scanning under production-equivalent configuration. |

Automated verification establishes the listed local behavior only. The unresolved deployment checks remain release criteria.
